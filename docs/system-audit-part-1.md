## 1. 结论摘要

1. 当前仓库是一个静态前端加 Cloudflare/D1 风格网络服务的应用，没有发现 `package.json`、构建脚本、容器配置或独立后端工程依赖清单。
2. 当前可读源码中没有发现本地预置题目、教材正文、知识点语料、教辅资料、试卷模板、JSON/CSV 内容包、向量数据库、搜索索引或缓存目录。`assets/js/data.js` 中的 `KNOWLEDGE` 为空、`PAPER_PRESETS` 为空，教材只有“网络服务配置版本”占位结构。
3. 前端仍保留旧版组卷与批改的业务实现，主要集中在大型单体文件 `assets/js/app.js`；题目生成、评分、解释、学情、资料处理也集中在 `assets/js/ai.js`，还没有按工作流拆分的 Schema、质量门槛、独立解题验证、费用记录和人工介入状态机。
4. `server/schema.sql` 只有一套宽泛的 D1 结构，业务内容主要落在通用 `records` JSON 表；`server/index.js` 的运行时建表只覆盖部分核心表，且没有独立迁移目录。题目、知识点、教材映射、地区模板、来源、向量、工作流运行记录等尚未形成专用数据模型。
5. 远端数据不能在本地静态仓库中完成可靠分类。通用 `records` 可能承载真实账号关联数据、教师创建内容、学生答题记录和旧资源，因此第 2 部分必须先做远端只读分类、备份、哈希和删除候选清单，不能直接执行全表清空或通用集合覆盖。
6. 当前仓库中可读取的源码未命中“福建、厦门、Fujian、Xiamen”等专属地区字样，但 3 个大文件被 macOS 标记为 `compressed,dataless`，读取会超时；因此最终删除前仍需对这些文件恢复可读后再做一次全局扫描。

## 3. 文件与数据处理清单

### 保留

- 程序源代码、运行依赖、公共品牌图标和环境配置模板。
- 真实用户账号、真实学生作业/答题/学习记录、真实教师创建的试卷/资源/批改记录。
- 账号、学校、班级、权限、公告、学年学期和审计日志等与本次内容资源清理无关的正常功能。
- `README.md` 等说明性文档；后续更新其与实际架构不一致的部分。

### 暂无本地删除对象

- 没有确认到本地预置题目、教材正文、知识点正文、教辅、地区卷、JSON/CSV 内容包、向量索引、搜索缓存或 seed 数据。
- `MOCK.KNOWLEDGE: []` 和 `PAPER_PRESETS: {}` 是结构占位，不应当被当作旧题库删除。
- `test-mode.js` 产生的是浏览器临时演示状态，不是仓库内容资源；后续需要隔离和过期清理，不应直接删除测试功能。

### 远端分类需要人工复核

远端 D1 的 `records` 表以 `collection_name` 加 JSON 记录承载多类数据。当前静态仓库不能证明某一条记录是旧题目、教师真实试卷、学生作业还是演示数据。因此在获得远端只读访问能力并完成分类前，不执行任何 `DELETE`、全集合替换或索引清理。

## 4. 可恢复备份与迁移方案（第 2 部分的前置条件）

### 4.1 备份范围

在任何删除或不可逆迁移之前，按学校和集合导出：

- `users`、`schools`、`campuses`、`classes`、成员/任教/课程开设关系。
- `records` 全量原始 JSON，包括已删除标记、创建者、更新时间、来源和审计关联字段。
- `audit_logs`、`sessions`、模型配置、模型同步记录。
- 已部署静态资源和当前 Git 提交引用。

备份必须写入带时间戳的独立目录，保留原始 JSON/CSV/SQL 导出、行数、字节数、SHA-256 校验值和导出日志；备份完成后先做一次可读取性与抽样恢复测试。当前尚未执行此备份，因为本地没有远端 D1 凭证和生产数据访问入口。

### 4.2 分类与干运行

迁移工具必须先输出候选清单，不直接删除。至少按以下字段分类：

- 记录集合、所属学校、创建者/所有者、创建时间、最后更新时间。
- 内容类型和 schema 版本：题目、教材元数据、知识点、试卷模板、教师资源、学生作业、批改、学习事件、演示数据。
- 来源类型、来源链接、是否真实用户创建、是否已被真实作业或试卷引用。
- 是否重复、是否失效、是否有审计日志、是否可由新系统重建。

只有同时满足“明确属于旧预置/演示资源、没有真实用户所有者、没有被真实记录引用、已完成备份”的记录，才进入删除候选。无法判定的记录默认保留并进入人工复核清单。

### 4.3 回滚

迁移使用新增版本字段和可逆标记优先；删除候选先软删除并保留原始快照。出现引用断裂、统计变化异常、登录/批改回归或用户数据缺失时，停止后续批次，用备份按集合恢复，并把恢复过程写入审计日志。确认观察窗口结束后，才讨论物理清理。
