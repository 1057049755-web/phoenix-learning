## 接口行为

接口需要管理员会话：

```text
GET /api/admin/content-audit
GET /api/admin/content-audit?collections=resources,papers&limit=500
GET /api/admin/content-audit?schoolId=<学校ID>
```

返回内容包括：集合计数、抽样记录、分类理由、记录哈希、所有者、更新时间、是否关联学生提交，以及固定的 `deletion.executed: false`。接口不支持 `DELETE`、`PUT` 或批量覆盖。

## 分类规则

| 分类 | 判定 | 默认处理 |
|---|---|---|
| `real_business` | 账号、班级、学习事件等真实业务集合 | 保留 |
| `student_record` | 作业、答题、批改或带学生/提交引用的记录 | 保留，不能随旧资源删除 |
| `paper_review` | 试卷记录，可能由教师真实创建 | 人工复核后保留或版本化 |
| `resource_review` | 资料或来源记录 | 核验所有者、版权和引用关系 |
| `content_review` | 题目、知识点、解析、标签等内容集合 | 核验来源、版本、引用关系 |
| `legacy_review` | 出现 `seed`、`fixture`、`preset`、`legacy` 等显式旧资源提示 | 进入候选清单，不自动删除 |
| `demo_candidate` | 显式测试/演示标记，且没有所有者和学生/作业引用 | 仅允许在备份和人工确认后处理 |
| `unknown_review` | 无法稳定识别 | 默认保留 |

## 真实备份执行顺序

1. 由管理员通过受保护的数据导出方式导出用户、学校、班级、记录、审计日志、模型配置和同步记录。
2. 保存原始 JSON/SQL、行数、字节数、SHA-256、导出时间和操作者；备份目录不得放入静态发布目录。
3. 对备份做可读性检查和抽样恢复测试，记录恢复结果。
4. 调用 `content-audit` 生成候选清单；对候选记录做引用检查、所有者确认和来源核验。
5. 仅将确认无真实用户关系的旧演示/预置记录写入 `content_audit_manifests`，决策状态先保持 `review_required`。
6. 首批采用软删除或停用标记，并观察登录、组卷、批改、学情和导出功能；不执行物理清理。
7. 发现异常时按备份恢复原始记录，并写入 `migration_runs` 与 `audit_logs`。
